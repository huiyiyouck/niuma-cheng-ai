### R2 修改记录（2026-07-26，PM）

**Owner 核心原则（2026-07-26 定，写入 PRD §0，优先级高于成本考量）**：以基础夯实、可扩展性强的方式开发，而不是图便捷；宁可现在多干活，也要让系统更健全、后期接入更友好。依据：ai 是持续迭代产品，基础越牢后续可扩展的功能越多。

按此准则推翻 R1 三处「成本最优解」：

| # | R1 成本最优解 | R2 裁定 |
|---|---|---|
| 1 | worker 跑独立线程绕开同步阻塞、处理核心零改造（Developer 问题 2 推荐①） | **改为 async 地基改造**（新增 US-8 / AC-9）——线程方案是绕过而非解决；同步阻塞是既有架构债，v0.3 工具并发必然要还，届时 worker 推倒重来 |
| 2 | 适配层 = 两个映射函数（Architect O-2 倾向） | **改为定义数据源协议**（AC-2.1）——映射函数方案下第二调用方要回来改我们代码 |
| 3 | `tags_v2` 第五类二选一 | **主张 `sentiment` 与 `processing` 两者都保留**（C-10）——二者非同类，丢任一削弱可诊断性 |

**其余修改**：AC-2/AC-8 判据分开写死（解 Developer 问题 4 的互斥）；AC-3 增补批量上限不变式（N ≤ 8，正确性约束）+ claim 原子性实证前置；AC-4 字段来源逐条标注 + 三段式事务 + 写入方式挂 C-3；AC-5 增补退避判定、重试真源、残留锁自愈、优雅停机；AC-6 增补 DSN 脱敏可验证断言、注入式 logging、降级事实冗余进日志；AC-7 删空条款（`stub` 已 0 命中）+ 缺陷定位订正至 `news_l1.py:150/179/213` + 扩为三工具统一语义；新增 AC-9（async 地基 + 处理中 `/health` 2s 响应）、AC-10（三类源实现 + 验收分层，不得虚报）；新增 §6 契约缺项清单 C-1~C-10、§8 工程成本与切片；§5 前置依赖按已就绪/待交付/届时前置三段重写；事实层刷新 8 项全部落实。

**新增开放问题**：O-8 async 改造的切分与回归策略（P0，本迭代最大技术风险，风险在回归不在重写）、O-9 DB 驱动选型须与 async 一致、O-10 `locked_by` 标识规则。
