### 对设计的三处偏离（均已在 commit 记明理由）

1. **步骤顺序调整**：设计步 1 只改工具层，但其完成判据要求「黄金样本通过」——工具改 async 后同步节点无法 await，系统在该步结束时跑不起来，判据不可能达成。实测 `ainvoke` 可执行同步节点，故把入口层提前到第一步。**偏离的是顺序，不是分层原则**；这是唯一能同时满足「分层」与「每步跑黄金样本」的顺序。
2. **`ItemBudget` 的位置**：设计写 `worker/budget.py`，但它要随 `L1State` 流经 graph，而 §1.3 要求处理核心对 `worker/` 零依赖——定义在 `worker/` 下会让处理核心反向 import 拉取型控制流的包。改放 `agent_hub/budget.py` 顶层（它本身是数据源无关的量，§4.5 亦如此认定）。已加静态测试固定该约束。
3. **`extract_url` 保持同步**：设计 §6.1 写「`NewsTools` 协议 4 方法改 async」，但它是纯字典取值 + 前缀判定、无 IO，按 O-8 的划线判据（「无 IO 且耗时毫秒级保持同步」）不应改协程。
