## 2026-08-01 — 裸批量暂存把 DevOps 未提交的回帖卷进我的 commit（G16 双实例之一）

- 现象：在 coordination 仓提交时用裸批量暂存，把 DevOps 写好但尚未提交的 REQ-003 回帖（约 40 行）一并提交进 `0cc7510`。内容本身完整、发布结果正常，但归属记错、commit message 范围不符。与同日数小时前 DevOps 的 `a2943e2`（其 `git add -A` 卷入 Architect 改动）**方向相反、同型失效**，两件合为 BCR-016 的实证与回归用例 G16 双实例。本条此前只存在于 DevOps corrections 的「镜像事件补记」里，PM 自己的记录零留痕——**当事方是我，留痕却靠别人补**，这本身也是个错。
- 修正：已推送且 [P0] 禁 force push，不改写历史。系统性修复走 BCR-016，已采纳且比原案更严：conventions.md 全面禁止裸 `git add -A` / `git add .`、无例外通道（真源 `9bdc949`，本仓回流 `da87d7c` 已核实落地）。
- 预防：提交一律 `git add <明确文件列表>`，批量场景也列固定路径清单。判据是「命令里根本没有 `-A`/`.`」——机器一眼可查，不依赖「人逐一比对 diff --stat」这个已被实证会失效的动作（人在收尾时倾向快速通过）。基线已强制，本条仍留档：我是当事方，规则落地不等于我可以不记。
